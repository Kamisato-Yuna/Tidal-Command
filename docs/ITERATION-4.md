# 第四次迭代：对战档案、收藏与逐发复盘

日期：2026-10-18。状态：实现完成，TypeScript、生产构建、153项自动化测试及17项真实浏览器回归全部通过。

## 对战记录与保留规则

- 战斗结束后自动归档，入口的「对战记录」可查看近期对局、筛选收藏并进入复盘。战报页提供「复盘本场」「收藏本场」及单局备份。
- 独立版本化存储键 `tidal-command:history:v1` 只存已结束、经过完整规则重放校验的对局。正在进行的自动存档仍使用原有键，两者互不替换。
- 自动保留最近50场未收藏对局；收藏不计入这50场，也不会被自动清理。取消收藏后重新适用近期保留规则。
- 没有手动删除或清空历史功能。只在成功的归档、收藏变更或导入事务中应用已说明的近期保留规则，不在读取或导出时清理。
- 旧版可恢复的已结束自动存档会按对局编号幂等迁入历史，保留原来的单发/允许相邻等旧规则。旧存档没有时间字段，因此列表时间为首次归档时间；失败后重试保留本页面记录的原始时间。

## 浏览器本地存储与失败处理

收藏表示应用不会自动清理，不代表服务器永久备份。记录只在当前浏览器内；清除站点数据、重置浏览器或更换设备均可能失去记录。界面明确提示这些限制，并提供JSON导出、导入。

每次修改先重新读取持久化历史，再进行合并，避免旧页面用旧快照覆盖另一页刚收藏的记录。存储事件同步列表。写入失败不先清空、不额外删收藏、不显示收藏成功；已保存原值保留。

未能归档的已完成对局暂留当前页面内存，跨页面仍提示风险，允许单局/全部导出和重试保存，并在离开网页时触发浏览器标准未保存提示。新对局可继续，但刷新或关页前应先备份。损坏或未来版本的历史不会被当成空历史覆盖，后续写操作被阻止，仍可导出当前可读或待保存的对局。

## JSON备份

- 格式标识 `tidal-command:match-history`、版本1、导出时间及完整已完成对局条目。
- 导入为合并，不替换已有记录。相同编号和相同内容去重，收藏标记只会合并保留，不会被普通导入取消；相同编号但不同对局内容拒绝整次导入。
- 文件、条目、舰队、规则、事件、齐射计划、胜负及可选诊断信息均校验；每局使用既有引擎重放验证，拒绝未结束、伪造或不一致记录。
- 导入在读取文件前检查20MiB大小，核心层再检查UTF-8字节长度。导出使用相同上限，成功导出的备份可被同版本导入。收藏不设条数上限，但仍受浏览器空间及文件大小限制，失败会明确提示。
- 导出不应用保留清理，也可单独导出尚未写入存储的完成对局。导入失败不更改既有历史或正在进行的对局。

## 只读复盘

部署帧加上每一发实际炮击组成时间轴，支持上一发/下一发、起点/终点、拖动进度、点击攻击记录跳转及0.5×/1×/2×/4×自动播放。

「我方视角」「对手视角」分别显示该方自己的完整舰队和当时已经击沉的对方舰船；未知舰位不会因最终战报的数据而提前进入3D渲染器。可切换攻击海域/己方海域，查看逐发结果、回合、齐射序号、轮内炮弹、命中率及当时的己方损伤。

复盘只消费已结束档案的不可变投影，不调用AI、不写自动存档、不创建可以续玩的半回合状态。多发齐射逐发回看；获胜提前终止时，只生成实际执行的帧，未发出的计划尾部不画成炮击。播放在拖动时间轴、切换视角/海域、打开设置或说明、页面隐藏、退出复盘时暂停或结束。
